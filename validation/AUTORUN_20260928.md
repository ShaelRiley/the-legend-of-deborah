## Defect and repair

`PlayerOptions:ApplyMove` raised the movement ceiling but left horizontal input
unchanged. A walking-sized request of 100 with a cap of 100 remained 100 after
enabling Always Run, even when the configured run speed and new cap were 200.
The same shortfall affects analog input. The old test examined only caps.

The existing shared method now converts both horizontal input components and
the effective cap by the existing walk/run ratio, before existing movement
effects. It resolves zero client cap (no extra native limit) from the move cap;
when both caps are positive, the stricter cap wins. Both published caps match.
No new hook, timer, setting, speed constant, native player-speed mutation or
button remapping was introduced. Vertical input and velocity are untouched.

An initial suspicion about a server-only setting API was ruled out against
Facepunch's shared API documentation; the setting lookup is unchanged.
